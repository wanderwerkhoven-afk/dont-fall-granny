# Inspiration Prototype — Joyride V9

The original HTML prototype is a design reference, not the production architecture.

## Keep

- Immediate endless-runner readability.
- One-button jump as the basic interaction.
- Collectible coins and temporary protection.
- Outfit unlocks and gadget unlocks.
- Short special-mode interruptions:
  - plane / aerial obstacle mode;
  - mobility-scooter lane mode.
- Escalating speed and changing environments.
- Ten-second post-fail decision window.
- Fast restart flow.
- Granny-first visual identity.

## Upgrade

### Movement
The HTML prototype uses binary jump-or-fail interactions. The production game adds balance, recovery, near-falls and readable states between safe and failed.

### Special modes
Plane and mobility-scooter segments become authored event sequences tied to the same tension/recovery language as the base game instead of feeling like unrelated minigames.

### Progression
Coins remain useful, but mastery is earned from player behaviour: Balance, Bravery and Chaos.

### Presentation
Canvas drawings are a useful style reference only. Production targets stylized 3D characters, animation, camera feedback, VFX and adaptive audio.

### Fail flow
The timed game-over choice is retained as a strong UX idea. The final version should present rescue/retry choices without creating pay-to-win pressure.

## Production rule

A feature from the prototype is kept only if it strengthens at least one of the project pillars:
character-driven chaos, skillful survival, premium game feel, replayability or visual identity.
